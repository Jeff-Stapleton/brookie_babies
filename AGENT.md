# AGENT.md

Guidance for AI coding agents (and humans) working in this repository.

## What this is

**Brookie Babies** is a Flutter **web** app: a marketing and booking site for a
photography business. Visitors see a full-screen photo carousel, choose a
session package (Basic / Premium / Ultimate), pick a date and session time, and
are sent to a Stripe Payment Link to pay.

- Firebase project: `brookie-babies` (see `.firebaserc`)
- Hosting: Firebase Hosting, serving the static `build/web` output
- Stage: early MVP. Much of the content is placeholder (see "Known gaps").

Although the `android/`, `ios/`, `macos/`, `linux/` and `windows/` folders exist
(from `flutter create`), **only web is supported**:
- `lib/firebase_options.dart` only configures web; every other platform throws
  `UnsupportedError` at startup.
- `lib/pages/checkout_page.dart` imports `flutter_stripe_web` and `package:web`,
  which only compile for web.

Always run and build with `-d chrome` / `flutter build web`.

## Tech stack

| Concern | Package |
|---|---|
| UI framework | Flutter (Material 3), Dart SDK `^3.5.3` |
| Firebase bootstrap | `firebase_core` |
| Carousel images | `firebase_storage` (lists `gs://brookie-babies.firebasestorage.app/_admin/gallery`) |
| Calendar | `table_calendar` |
| Payments | Stripe Payment Links via `url_launcher`; `flutter_stripe` / `flutter_stripe_web` (experimental checkout page) |
| Auth | `firebase_auth` is a dependency but is **not used** anywhere yet |
| Lints | `flutter_lints` (`analysis_options.yaml`, default rules) |

## User flow

1. `HomePage` → `CarouselExample` loads every file in Storage `_admin/gallery` and
   cross-fades through them every 10s. "Book Now" scrolls to the packages.
2. `Packages` → `PricingCard` "Book Now" → `Navigator.push(SchedulingPage(packageName))`.
3. `SchedulingPage` → user selects a day → tapping any `SessionCard` calls
   `navigateCheckout()`, which opens the Stripe Payment Link for that package
   (`buy.stripe.com/...` URLs hard-coded in `scheduling_page.dart`).

Named routes `/schedule` and `/checkout` exist in `main.dart` but the main flow
does not use them (`/schedule` passes an empty package name, which falls through to
"Unknown package type").

## Commands

```bash
flutter pub get                 # install deps
flutter run -d chrome           # run locally (web)
flutter analyze                 # lints
flutter test                    # tests (Dart VM)
flutter build web               # production build -> build/web
firebase deploy --only hosting  # manual deploy: run flutter build web first (build/web is what gets deployed)
```

CI (`.github/workflows/ci.yml`) runs `flutter pub get --enforce-lockfile`,
`flutter analyze --no-fatal-infos`, `flutter test` and
`flutter build web --release` on Flutter 3.24.3, then fails if `build/web`
contains a Stripe secret key. If those pass, it deploys a preview channel for
pull requests and the live site for pushes to `main`.

Storage CORS (needed for the carousel images to load in the browser):

```bash
gsutil cors set cors.json gs://brookie-babies.firebasestorage.app
```

## Conventions

- Imports use `package:brookie_babies/...` (one or two files use relative imports;
  prefer the package form).
- Widgets are mostly `StatelessWidget` with `const` constructors and `super.key`.
- Text styling goes through the `widgets/*_text.dart` wrappers rather than
  inline `TextStyle`s; reuse them.
- Put new screens in `pages/`, page sections in `components/`, reusable leaf
  widgets in `widgets/`.
- Logging uses `dart:developer`'s `log()`; `page_footer.dart` still uses `print`.

## Known gaps / gotchas

- **SECURITY: a live Stripe secret key (`sk_live_...`) is hard-coded in
  `lib/main.dart`** for the `/checkout` route and is committed to git. Secret keys
  must never ship in client code. It should be revoked in the Stripe dashboard,
  removed from the source (and ideally git history), and replaced by a
  server-created PaymentIntent `client_secret` (e.g. from a Cloud Function).
  Never add new secrets to this repo. CI's Stripe key check fails every run
  until this key is removed.
- `build/` is committed to git (Flutter build output). It should be in `.gitignore`.
  CI deletes it before building.
- Lint infos are not fatal in CI yet; analyzer warnings and errors are.
- Tests run on the Dart VM, so they must not import `main.dart` or
  `checkout_page.dart`, which pull in web-only libraries. `HomePage` also needs
  Firebase (the carousel calls Firebase Storage). The only test is a smoke test
  of `Packages`.
- Placeholder content: lorem ipsum in `text_section.dart`; all three packages share
  the same bullets; session times, address and description in `session_card.dart`
  are hard-coded; footer social buttons only `print`; copyright says
  "Your Company Name"; `MaterialApp.title` is "Flutter Demo"; `pubspec.yaml` and
  `web/index.html` descriptions are "A new Flutter project."
- Selected date and time are not passed to Stripe or stored anywhere, so
  bookings are not recorded.
- `package:web` is imported in `checkout_page.dart` but not declared in
  `pubspec.yaml` (it only resolves transitively).
- `CarouselExample._timer` is `late` and is only assigned after the Storage call
  completes, so disposing the widget before that throws.
